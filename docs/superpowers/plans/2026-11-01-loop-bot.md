# loop-bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 유튜브 링크·음원 파일을 사용자당 하나의 플레이리스트로 모으고, 미니앱에서 순서를 드래그로 정해 텔레그램 기본 플레이어로 이어 재생하게 하는 봇을 맥에서 실행한다.

**Architecture:** python-telegram-bot(long polling) 봇이 yt-dlp로 유튜브 음원을 m4a로 받아 `send_audio`로 올리고, 돌려받은 `file_id`를 SQLite에 저장한다. 재생은 저장된 `file_id`를 순서대로 다시 보내는 것. 미니앱은 정적 HTML 한 장(GitHub Pages)으로, 목록을 URL hash로 받고 결과를 `Telegram.WebApp.sendData`로 돌려준다.

**Tech Stack:** Python 3.14, python-telegram-bot 22.x, yt-dlp, ffmpeg, deno(yt-dlp의 YouTube JS 런타임), sqlite3(stdlib), pytest, SortableJS 1.15.6(cdnjs), telegram-web-app.js.

**Spec:** `docs/superpowers/specs/2026-11-01-loop-bot-design.md`

## Global Constraints

- 사용자에게 보이는 모든 문구는 한국어 `-요` 체. 문구는 스펙 "오류 처리" 표 그대로.
- 접근 허용: `.env`의 `ALLOWED_USER_IDS`(쉼표 구분 정수)만.
- 유튜브 호스트: `youtube.com`, `www.youtube.com`, `m.youtube.com`, `music.youtube.com`, `youtu.be`. http/https만.
- 한 번에 추가 가능한 링크: 최대 10개. 영상 길이: 최대 3600초. 업로드 파일: 최대 49MB(49*1024*1024 bytes).
- 미니앱 제목 표시: 40자로 자름. payload 버전 `v: 1`.
- 재생 전송 간격 0.5초, `RetryAfter`면 `retry_after`초 대기 후 같은 곡 재시도.
- 다운로드는 한 번에 하나(전역 `asyncio.Lock`). 다른 업데이트는 막지 않도록 `concurrent_updates(True)`.
- 임시 다운로드 파일은 성공·실패와 무관하게 삭제(`tempfile.TemporaryDirectory`).
- Docker 금지. 실행은 venv + `python -m loopbot`.
- 비밀값(BOT_TOKEN)은 `.env`에만, `.env`는 git 제외.

### 스펙 대비 변경 1건

스펙은 "payload의 `order`에 없는 id는 삭제"였지만, 미니앱을 연 뒤 새 곡이 추가되면 그 곡이 지워지는 문제가 있다. 그래서 payload에 삭제 목록 `removed`를 명시한다:
`{"v":1,"order":[3,1,2],"removed":[5],"add":["https://..."],"play":true}`
- `removed`에 있는 내 id는 삭제.
- 남은 곡은 `order` 순서대로 앞에 두고, `order`에 없는 곡(미니앱 이후 추가된 곡)은 기존 순서대로 뒤에 붙인다.
- 이미 없는 id(다른 경로로 삭제된 곡)는 오류 없이 무시한다. 형식 오류(깨진 JSON, `v != 1`, 정수 배열 아님, 링크 11개 이상, 유튜브가 아닌 링크)만 거부한다.
Task 1에서 스펙 문서의 해당 문단도 이 내용으로 고친다.

## Review Focus

1. **미니앱을 연 사이 목록이 바뀜** → 새 곡은 유지되고 뒤에 붙어야 함. Task 3 `test_apply_order_keeps_tracks_added_after_snapshot`.
2. **한글·이모지 제목이 URL hash를 통과** → 깨지지 않아야 함(UTF-8 base64url). Task 4 `test_build_webapp_url_roundtrips_korean_and_emoji`, 미니앱은 `TextDecoder`로 디코드.
3. **다양한 유튜브 링크 형태**(`youtu.be/x?si=...`, `/shorts/`, `music.youtube.com`, 스킴 없는 `youtube.com/watch`) → shorts·music·si는 허용, 스킴 없는 것은 거부(안내 문구). Task 4 `test_is_youtube_url_variants`.
4. **다운로드 중 다른 동작** → 다운로드 중에도 `/list`·재생이 응답해야 함. Task 6 `concurrent_updates(True)`, 수동 확인 단계에 포함.
5. **제목 없는 음원 파일**(document, 메타데이터 없음) → 파일명, 그것도 없으면 `"제목 없음"`. Task 6 `test_title_for_audio_fallbacks`.

### Task 4: 링크 검증·미니앱 URL·payload 파싱

**Files:**
- Create: `loopbot/payload.py`, `tests/test_payload.py`

**Interfaces:**
- Consumes: Task 2 `Track`
- Produces:
  - 상수 `MAX_LINKS = 10`, `TITLE_MAX = 40`
  - `is_youtube_url(text: str) -> bool` — `urllib.parse.urlsplit`, scheme ∈ {http, https}, hostname(소문자) ∈ Global Constraints 호스트 목록.
  - `extract_youtube_urls(text: str) -> list[str]` — 공백으로 나눈 토큰 중 `is_youtube_url`인 것, 순서 유지·중복 제거.
  - `build_webapp_url(base: str, tracks: Sequence[Track]) -> str` — `base + "#d=" + base64url(utf-8 JSON [{"i": id, "t": title[:TITLE_MAX]}])`, 패딩 `=` 제거, JSON은 `separators=(",", ":")`, `ensure_ascii=False`.
  - `class PayloadError(ValueError)` — 메시지는 사용자 안내 문구.
  - `@dataclass(frozen=True) class WebAppAction: order: tuple[int, ...]; removed: tuple[int, ...]; add: tuple[str, ...]; play: bool`
  - `parse_action(raw: str) -> WebAppAction` — 키 누락 시 빈 값/False. 거부 조건과 메시지:
    - 깨진 JSON, dict 아님, `v != 1`, `order`/`removed`가 int 배열 아님(bool 제외), `add`가 str 배열 아님, `play`가 bool 아님 → `PayloadError("목록이 바뀌었어요. 버튼을 다시 눌러주세요")`
    - `add` 11개 이상 → `PayloadError("링크는 한 번에 10개까지 넣을 수 있어요")`
    - `add`에 유튜브 아닌 것 → `PayloadError("유튜브 링크나 음원 파일만 받을 수 있어요")`

- [ ] **Step 1: 실패하는 테스트**

```python
import base64, json, pytest
from loopbot.db import Track
from loopbot.payload import (is_youtube_url, extract_youtube_urls, build_webapp_url,
                             parse_action, PayloadError, WebAppAction)

def test_is_youtube_url_variants():
    ok = ["https://youtu.be/abc?si=xyz", "https://www.youtube.com/watch?v=abc",
          "https://youtube.com/shorts/abc", "https://music.youtube.com/watch?v=abc",
          "http://m.youtube.com/watch?v=abc"]
    bad = ["youtube.com/watch?v=abc", "https://evil.com/youtube.com", "https://youtube.com.evil.com/x",
           "ftp://youtu.be/abc", "그냥 글"]
    assert all(is_youtube_url(u) for u in ok)
    assert not any(is_youtube_url(u) for u in bad)

def test_extract_youtube_urls_from_mixed_text():
    text = "이거 https://youtu.be/a 랑\nhttps://youtu.be/b https://youtu.be/a 들어봐"
    assert extract_youtube_urls(text) == ["https://youtu.be/a", "https://youtu.be/b"]

def test_build_webapp_url_roundtrips_korean_and_emoji():
    t = Track(7, 1, 0, "가" * 50 + "🎵", "f", None, None)
    url = build_webapp_url("https://x.io/app/", [t])
    enc = url.split("#d=", 1)[1]
    data = json.loads(base64.urlsafe_b64decode(enc + "=" * (-len(enc) % 4)).decode())
    assert url.startswith("https://x.io/app/#d=")
    assert data == [{"i": 7, "t": "가" * 40}]

def test_parse_action_full():
    raw = json.dumps({"v": 1, "order": [3, 1], "removed": [2], "add": ["https://youtu.be/a"], "play": True})
    assert parse_action(raw) == WebAppAction((3, 1), (2,), ("https://youtu.be/a",), True)

def test_parse_action_defaults():
    assert parse_action('{"v":1}') == WebAppAction((), (), (), False)

@pytest.mark.parametrize("raw", ["not json", "[]", '{"v":2}', '{"v":1,"order":["1"]}',
                                 '{"v":1,"order":[true]}', '{"v":1,"play":"yes"}'])
def test_parse_action_rejects_malformed(raw):
    with pytest.raises(PayloadError, match="버튼을 다시"):
        parse_action(raw)

def test_parse_action_rejects_too_many_links():
    raw = json.dumps({"v": 1, "add": [f"https://youtu.be/{i}" for i in range(11)]})
    with pytest.raises(PayloadError, match="10개"):
        parse_action(raw)

def test_parse_action_rejects_non_youtube_link():
    with pytest.raises(PayloadError, match="유튜브"):
        parse_action('{"v":1,"add":["https://evil.com"]}')
```

### Task 5: 유튜브 음원 추출

**Files:**
- Create: `loopbot/youtube.py`, `tests/test_youtube.py`

**Interfaces:**
- Produces:
  - 상수 `MAX_DURATION = 3600`, `MAX_BYTES = 49 * 1024 * 1024`
  - `class FetchError(Exception)` — `str(e)`가 사용자에게 보일 짧은 사유.
  - `@dataclass(frozen=True) class Audio: path: Path; title: str; duration: int | None; performer: str | None`
  - `check_limits(info: Mapping[str, Any]) -> None` — `info.get("duration")`가 있고 > `MAX_DURATION`이면 `FetchError("너무 길어요 (최대 60분)")`. `info.get("is_live")`가 참이면 `FetchError("라이브 방송은 받을 수 없어요")`.
  - `fetch_audio(url: str, workdir: Path, cookies: str | None) -> Audio` — 동기 함수(호출 측이 `asyncio.to_thread`). `yt_dlp.YoutubeDL` 옵션: `format="bestaudio[ext=m4a]/bestaudio"`, `postprocessors=[{"key": "FFmpegExtractAudio", "preferredcodec": "m4a"}]`, `outtmpl=str(workdir / "%(id)s.%(ext)s")`, `noplaylist=True`, `quiet=True`, `cookiefile=cookies`(있을 때만). 순서: `extract_info(url, download=False)` → `check_limits` → `download` → `workdir`에서 `.m4a` 파일 찾기 → 크기 > `MAX_BYTES`면 `FetchError("파일이 너무 커요 (최대 49MB)")`. `yt_dlp.utils.DownloadError`는 `FetchError`로 감싸되, 메시지에 `"Sign in to confirm"`이 있으면 `"유튜브가 서버 접근을 막았어요 (쿠키 필요)"`, `"Private video"`면 `"비공개 영상이에요"`, 그 외 `"영상을 받지 못했어요"`.
