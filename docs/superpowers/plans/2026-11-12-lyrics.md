# 실시간 가사 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 봇이 곡을 받을 때 LRCLIB에서 싱크 가사를 찾아 저장하고, 미니앱 전체 플레이어에 지금 줄이 강조되는 가사를 보여 준다.

**Architecture:** 새 표 `track_lyrics`에 곡마다 가사 1개. 봇(파이썬)이 추가 시점에 검색해 저장하고, 기존 곡은 채우기 스크립트로 한 번 채운다. Edge Function이 가사 읽기·후보 검색·고르기·싱크 저장을 맡고, 미니앱은 LRC를 파싱해 `#player-hero`에 그린다.

**Tech Stack:** Python 3 (표준 `urllib`, psycopg), Deno Edge Function (postgres.js), 바닐라 ES 모듈, `node --test`, `pytest`, `deno test`.

**Spec:** `docs/superpowers/specs/2026-11-12-lyrics-design.md`

## Global Constraints

- 출처는 LRCLIB 하나: `https://lrclib.net/api/search`, `https://lrclib.net/api/get/{id}`. User-Agent는 `loopbot (lyrics)`.
- 바깥 요청 시간 제한 8초. 실패해도 곡 추가·화면은 막지 않는다.
- 길이 차이 허용치 15초. 싱크 가사(`syncedLyrics`)가 없는 후보는 쓰지 않는다.
- 싱크값 `offset_ms`는 -30000..30000 정수, 화면 단위 500ms.
- 편집 권한(후보 검색·고르기·싱크 저장)은 **기존 영상 저장과 같은 규칙**: `requireAdmin` + 곡 주인(`ownsTrack`). 읽기는 `readableFilter`.
- 경로는 기존 모양을 따른다: `/tracks/:id/lyrics`, `/tracks/:id/lyrics/candidates`, `/tracks/:id/lyrics/offset`. (설계 문서의 `/lyrics/:id`와 뜻은 같다.)
- 비밀값·DB 주소는 출력하지 않는다. 글자는 `textContent`로만 넣는다.
- 미니앱은 `/tracks/:id/lyrics`가 404·실패면 지금처럼 제목만 보여 준다.

## Review Focus

1. 유튜브 제목이 지저분할 때 (가수 접두어, `|`, `/ English`, `(Official Video)`, `[LIVE]`, `(찬송가 91장/피아버전)`) → 정리된 검색어가 한국어 곡명만 남는다. Task 2 `clean_title` 표 테스트.
2. LRCLIB가 느리거나 죽음 → 곡 추가는 성공, 가사는 행 없음(다음 채우기 때 다시 시도). Task 3 테스트.
3. LRC에 한 줄에 시간표가 여러 개, 빈 줄, `[ar:]` 메타, `[00:12]`처럼 소수 없는 시간 → 바르게 파싱. Task 6 `parseLrc` 테스트.
4. 싱크값으로 위치가 0보다 앞서거나 첫 줄 전 → `lineAt`이 -1, 화면은 첫 줄을 흐리게. Task 6 테스트.
5. 곡을 빠르게 넘길 때 늦게 온 이전 곡 가사가 덮어쓰기 → 곡 id 확인 후 그린다. Task 7 확인.

```ts
// lrclib.ts
export interface Candidate { id: number; track: string; artist: string; duration: number }
export function cleanTitle(title: string): string            // Task 2 규칙과 같은 결과 (performer 없이)
export async function searchCandidates(q: string, fetchFn = fetch): Promise<Candidate[]>  // 싱크 있는 것만, 최대 8개
export async function getSynced(id: number, fetchFn = fetch): Promise<string | null>
// db.ts (Db 인터페이스에 추가)
lyrics(userId: number, id: number): Promise<{ status: "found" | "none" | "unknown"; synced: string | null; offset_ms: number } | null>  // 못 읽는 곡이면 null

trackTitle(userId: number, id: number): Promise<string | null>                            // 후보 검색 기본 검색어용, ownsTrack
```

| 요청 | 응답 |
|---|---|
| `GET /tracks/:id/lyrics` | `{status, synced, offset_ms}`; null이면 404 |
| `GET /tracks/:id/lyrics/candidates?q=` | `requireAdmin`; q 없으면 `cleanTitle(trackTitle)`; q는 1..100자; `{q, candidates}` |
| `PUT /tracks/:id/lyrics` `{lrclib_id}` | `requireAdmin`; 양의 정수 검사; `getSynced` null이면 422 `no_synced`; 저장 후 `{status:'found', synced, offset_ms}` |
| `PUT /tracks/:id/lyrics/offset` `{offset_ms}` | `requireAdmin`; 정수로 반올림 후 -30000..30000 자르기; `{offset_ms}` |

### Task 6: 미니앱 LRC 로직

**Files:**
- Create: `webapp/lrc.js`
- Test: `tests/webapp/lrc.test.mjs`

**Interfaces — Produces:**
```js
export function parseLrc(text) // -> [{ t: number(초), text: string }] 시간순
export function lineAt(lines, position, offsetMs) // -> 지금 줄 index, 첫 줄 전이면 -1
```
- [ ] **테스트 먼저**:
  - `"[00:12.50]가\n[00:15.00]나"` → `[{t:12.5,text:'가'},{t:15,text:'나'}]`
  - `"[00:20.00][01:20.00]후렴"` → 두 줄 (t 20, 80), 정렬됨
  - `"[ar:F.I.A]\n[ti:곡]\n[00:01.00]첫"` → 메타 무시, 한 줄
  - `"[00:05]소수 없음"` → t 5
  - `"[00:03.00]\n[00:04.00]다음"` → 빈 줄은 text `''`로 남는다 (간주 표시용)
  - `lineAt(lines, 14, 0)` → 0; `lineAt(lines, 11, 0)` → -1; `lineAt(lines, 12, 1000)` → 0 (offset 양수 = 가사를 일찍); `lineAt([], 5, 0)` → -1
  - offset 의미: 화면 시간 = 재생 위치 + offset_ms/1000.
