# 공유 가사집

날짜: 2026-11-02

## 목표

관리자가 올린 플레이리스트와 가사 사진을 등록된 모두가 같이 본다. 각자 곡을 들으며 가사를 보고, 느낀점을 쓰고, 복사해서 가져간다.

성공 기준:

- 관리자가 플레이리스트를 공유하면 등록된 사람 모두의 선택칸에 나타난다.
- 공유 목록의 곡을 내려받아 재생할 수 있고, 화면을 꺼도 이어진다.
- 곡마다 가사 사진을 보고 크게 확대할 수 있다.
- 느낀점은 본인만 보고, 저장되며, 복사 버튼으로 가져간다.
- 관리자 아닌 사람은 공유 목록, 곡, 사진을 바꿀 수 없다.

범위 밖: 느낀점 모아 보기와 다른 사람 글 읽기, 관리자 여러 명을 위한 화면, 사진 속 글자 인식, 곡당 사진 여러 장. 영상 작은 창은 아래 "다음 단계"로 따로 한다.

## 역할

- **관리자:** 새 비밀값 `LOOPBOT_ADMIN_USER_IDS`의 숫자 id만. username으로는 관리자가 될 수 없다. username은 다른 사람이 가져갈 수 있기 때문이다.
- **멤버:** 지금 허용된 모든 사용자. 자기 라이브러리와 목록은 지금처럼 쓴다.
- 봇은 바뀌지 않는다. 곡을 받으면 보내는 사람의 활성 목록에 붙는다. 관리자는 평소처럼 곡을 넣은 목록을 공유한다.

## 데이터

`supabase/migrations/004_shared_lyrics.sql`, `loopbot`과 `loopbot_test` 양쪽:

```sql
alter table playlists add column shared boolean not null default false;

create table track_sheets (
  track_id bigint primary key references tracks (id) on delete cascade,
  file_id text not null,
  version integer not null default 1  -- 사진을 바꾸면 올려서 캐시를 무효화한다
);

create table track_notes (
  user_id bigint not null,
  track_id bigint not null references tracks (id) on delete cascade,
  body text not null,
  updated_at timestamptz not null default now(),
  primary key (user_id, track_id)
);
```

- 두 테이블 모두 지금 테이블과 같이 RLS를 켜고 `loopbot_app`에 권한을 준다.
- 곡을 목록에서 빼도 느낀점은 남는다. 곡 자체를 라이브러리에서 지우면 모두의 느낀점도 지워진다. 관리자의 삭제 확인 문구에 이를 적는다.

곡을 읽을 수 있는 조건을 한 곳에 둔다: **내 곡이거나, 공유 목록에 든 곡.** `fileId`와 새 함수가 모두 이 조건을 쓴다.

## 함수 API

`GET /state`에 더한다:

```js
{
  // 기존: library, playlists(본인 것, shared 포함), active_id
  shared_playlists: [{id, name, track_ids}], // 남이 공유한 목록. 읽기 전용
  shared_tracks: [{id, title, duration}],    // 그 곡들. 내 라이브러리와 별개
  sheets: {[trackId]: version},              // 읽을 수 있는 곡 중 사진 있는 것
  notes: {[trackId]: body},                  // 내 느낀점
  is_admin,
}
```

| 요청 | 누가 | 동작 |
|---|---|---|
| `GET /tracks/:id/file` | 읽을 수 있는 사람 | 지금과 같다 |
| `GET /tracks/:id/sheet` | 읽을 수 있는 사람 | 사진 바이트 |
| `PUT /tracks/:id/sheet` | 관리자, 자기 곡 | 이미지 바이트를 받아 저장 |
| `DELETE /tracks/:id/sheet` | 관리자, 자기 곡 | 사진 삭제 |
| `PUT /tracks/:id/note` | 읽을 수 있는 사람 | `{body}` 저장. 비면 행 삭제. 10,000자 초과는 400 |
| `PUT /playlists/:id/shared` | 관리자, 자기 목록 | `{shared}` |

- 기존 `PUT /playlists/:id`, `DELETE /playlists/:id`, `PUT /active`, `DELETE /tracks/:id`는 소유자만 된다는 지금 규칙을 유지한다. 멤버가 공유 목록에 보내면 404다.
- `PUT .../sheet`: 함수가 관리자 채팅에 `sendDocument`로 보내 `file_id`를 받고 그 메시지를 바로 지운다. `sendPhoto`는 다시 압축해 가사가 뭉개질 수 있어 쓰지 않는다. 본문은 `image/jpeg`이고 10MB 초과는 413이다.
- 사진 저장 전 `file_id` 응답이 없으면 502이고 기존 사진은 그대로 둔다.

## 미니앱

선택칸: 공유 목록을 `공유` 묶음(`<optgroup>`)으로 따로 보여 준다. 공유 목록을 고르면 `PUT /active`를 보내지 않는다. 봇이 받는 곡은 계속 내 목록에 붙는다.

재생 순서 카드 위에 `목록 / 가사집` 전환을 둔다. 공유 목록은 가사집으로 열리고, 관리자의 자기 목록은 목록으로 열린다. 멤버의 자기 목록에는 전환이 없다.

가사집 보기는 곡마다 세로로 쌓인 카드다:

1. 곡 제목. 누르면 재생. 재생 중인 곡을 강조한다.
2. 가사 사진. 폭에 맞춰 보여 주고 `loading="lazy"`로 화면에 가까워질 때 받는다. 누르면 전체 화면에서 핀치로 확대한다.
3. `느낀점` 입력칸과 `복사` 버튼. 사진 유무와 상관없이 있다.
4. 관리자의 자기 곡에만 `사진 넣기`, `바꾸기`, `지우기`.

공유 목록을 보는 멤버에게는 드래그, 빼기, 이름 바꾸기, 삭제, 라이브러리 카드를 숨긴다. 관리자는 자기 목록의 위 줄에 공유 켜기 버튼을 갖는다.

느낀점 저장:

- 입력을 멈추고 0.5초 뒤 저장한다. 곡마다 `saver.js` 저장기를 하나씩 쓴다.
- 입력할 때마다 `localStorage`에도 둔다. 저장이 끝나면 지운다. initData는 24시간이 지나면 거부되므로, 오래 열어 둔 채 쓴 글을 잃지 않아야 한다. 다시 열면 남은 임시 글을 서버 값보다 우선해 다시 저장한다.
- 복사: `navigator.clipboard.writeText`, 실패하면 입력칸을 선택해 `execCommand('copy')`. 끝나면 버튼이 잠깐 `복사됨`으로 바뀐다. 비어 있으면 비활성이다.
- 저장 실패는 지금처럼 위쪽에 알리고 다시 시도한다.

사진 올리기: 고른 사진을 긴 변 2400px, JPEG 품질 0.9로 줄여 보낸다. 사진은 Cache Storage에 `sheet-<id>-<version>` 키로 둔다.

재생은 바뀌지 않는다. `audio.js`와 `queue.js`는 그대로 쓰고, 재생 목록을 공유 목록에서 가져오도록 `playlistIds`만 넓힌다. 곡 이름 표도 `library`와 `shared_tracks`를 합쳐 만든다.

## 제한

- **전송량:** Supabase 무료 5GB를 haru와 나눠 쓴다. 곡 5MB와 사진 0.5MB를 25명이 받으면 곡당 약 138MB다. 30곡이면 약 4GB로 한 달 한도에 가깝다. 공유 곡 수가 많으면 유료 전환이나 곡 전달 방식 변경이 필요하다.
- 공유 곡도 20MB를 넘으면 미니앱에서 재생할 수 없다.
- 함수가 받을 수 있는 요청 크기는 2단계에서 실제로 확인한다.

## 순서와 확인

1. **DB와 함수.** 마이그레이션. Deno 테스트로 읽기 조건, 멤버의 쓰기 거부, 남의 느낀점 접근 불가, username 사용자가 관리자 경로 거부, 공유 해제 후 접근 거부를 `loopbot_test`에 돌린다.
2. **사진 경로.** 실제 텔레그램으로 사진을 올리고, 메시지 삭제 뒤 받아 본다.
3. **미니앱.** 가짜 API로 관리자와 멤버 화면을 375px에서 확인한다. 재생 중 느낀점 쓰기와 임시 글 복구를 확인한다.
4. **배포.** 사용자 승인 후 비밀값, 마이그레이션, 함수, 페이지 순서로 올린다. 모두 추가 작업이라 기존 사용자에게 영향이 없다.
5. **휴대폰 확인.** 관리자와 멤버 한 명씩. 사진 확대, 복사, 화면 끈 재생.

## 다음 단계: 참고 영상

가사를 보면서 가수의 동작과 표정을 참고한다. 가사집과 따로 만들어 위 일정에 영향을 주지 않는다. 시작 전에 텔레그램 웹뷰에서 유튜브 임베드가 재생되는지 휴대폰으로 시험한다. 안 되면 유튜브 앱으로 여는 링크로 대신한다.

- 관리자가 곡마다 참고 영상 링크를 넣는다. 음원을 받은 영상과 다른 무대 영상을 고를 수 있어야 하기 때문이다. `track_sheets`에 `video_id`를 더하고, 유튜브 링크에서 뽑은 id만 저장한다.
- 영상은 유튜브 임베드로 재생한다. 내려받지 않아 Supabase 전송량이 들지 않는다. 임베드를 막은 영상은 재생되지 않는다.
- 구석의 작은 창이 아니라 화면 폭에 맞춰 맨 위에 고정한다. 작은 창으로는 표정과 동작이 잘 보이지 않는다. 그 아래에서 가사와 느낀점을 스크롤한다. 시스템 PIP는 임베드를 제어할 수 없어 쓰지 않는다.
- 영상을 여는 동안 재생 바를 숨겨 세로 공간을 확보하고, 오디오는 멈춘다. 영상을 닫아도 오디오를 자동으로 다시 틀지 않는다.
- 일시정지, 되감기, 재생 속도는 유튜브 플레이어의 기능을 그대로 쓴다.
- 화면을 끄면 영상은 멈출 수 있다.
